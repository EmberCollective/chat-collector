# Windows 安装与首次使用

当前交付为 **Windows x64 本地使用预览包**。解压 `chat-collector-windows-x64-preview.zip`，双击其中的 `Install.cmd`，选择安装目录，再按窗口引导配置。无需预先安装 Python、Node、Git 或编译器；安装需要联网。已有部署请使用其配置入口，不要把新包覆盖到正在运行的项目上。

## 首次操作

1. 选择空的安装目录，默认 `D:\opt\chat-collector`。若该目录已有内容，选择另一个目录；安装器不会清空或覆盖现有部署。
2. 安装器校验包内文件，下载并校验 Python 3.13.8、Node 22.21.1 和上游 `wx_key` 原生组件，再安装依赖和锁定版本的 Pi 1.5.2。运行环境位于项目内，不改系统 Python 或系统 PATH。
3. 选择微信、QQ 或两者。自动发现 Windows“文档”位置下的默认数据目录；自定义位置可手动选择。核对账号、扫描间隔、数据库刷新间隔和附件强度。
4. 填写模型接口地址、模型名和 API Key。Pi 的分组、工具、原生压缩和预算初值沿用项目当前配置；模型实际上下文上限、最大输出、压缩预留必须匹配服务能力。密钥隐藏输入，保存本机 `.env`，不会写入包内或发到飞书。
5. 按需配置飞书；也可先跳过，以后通过现有渠道配置接入。完成对应平台取钥与解密验证。
6. 确认首次模型处理，等待最近 7 日符合 SQL 规则的消息全部处理完成。选择是否在当前用户登录 Windows 后自动启动。
7. 自动服务启动后打开本机调试台，查看采集、处理、投递与回写状态。

关闭窗口或某一步失败，配置和进度保留在 `data/install/progress.json`。重新运行安装目录中的 `Configure.cmd` 可继续；可修正未完成平台的路径/凭据和模型配置。不要删除 `data`、`secrets` 或 `.env` 来“重置安装”。

## 微信与 QQ 取钥

| 平台 | 首次取钥方式 | 需要用户完成 |
|---|---|---|
| 微信 | 上游 `wx_key` 原生 Hook；取得凭据后解密临时联系人库验证，通过才保存 | 保持微信可登录，按提示授权管理员权限，明确确认重启微信后重新登录 |
| QQ | 随项目保留的开源只读内存扫描器；通过 SQLCipher 验证数据库副本 | QQ 保持登录，允许管理员读取对应进程 |
| 已有凭据 | 直接指定已有密钥 JSON | 核对账号对应关系；解密验证不通过时不会宣称成功 |

没有重新编写取钥或反编译引擎。微信组件下载自 `LifeArchiveProject/WeChatDataAnalysis` 固定提交，轮子版本为 2.0.1、CPython 3.13、Windows x64；QQ 扫描器沿用原项目。客户端升级可能使取钥失效，需更新上游组件或导入可信的有效凭据，不能靠反复重试保证兼容。

首次完整解密会保留经过验证的明文快照；后续按变化页增量刷新，沿用原有回滚与完整性校验。私有 Python 的 SQLCipher 扩展和原生变化页引擎随预览包提供，用户不需要编译。

**数据库密钥不等于图片密钥。** 微信新取的数据库凭据不自动证明图片 AES/XOR 密钥正确；引导允许复用包含 `image_key_verified` 的已有凭据、明文图片缓存和 `VoipEngine.dll`。缺少图片密钥或解码组件时，相关附件保持未解析状态，不能声称所有图片都可读。旧 Word `.doc` 转换仍需单独安装 LibreOffice；PDF、DOCX 和支持格式图片由已安装的读取工具处理。

## 首次最近 7 日与后续增量

引导开始时记录固定的 `[开始时间, 结束时间)`，跨度 604800 秒。首次收集使用现有 SQL 规则集（默认 @所有人、文件和同会话上下文），不是把全部聊天都发送给模型。处理层的 `input.start_at` 使用相同下界。

每个平台先完成该时间段的持久采集与导出，再建立后续增量边界；失败重跑复用原时间段，由已有消息去重机制处理重复。处理按 `max_groups_per_round` 分轮推进到没有待处理分组才标记首次完成，不能只处理第一批就结束。

安装完成后，采集从已保存边界继续。自动处理检查有无待处理或变化分组，没有变化时不请求模型；修改规则、上下文或模型配置可能触发重新处理。安装期间的新消息由随后的正常增量轮次收集。

## 飞书官方配置与验证

借鉴 [codex-reset-monitor](https://github.com/YuShenLiu06/codex-reset-monitor/tree/97c4bd84aa8e2b18d56d0fa6e3adc052a57530b6) 的官方注册页引导方式，本项目直接调用已安装的 `lark_oapi.aregister_app`，不复制另一套 OAuth/注册协议。

引导请求以下 tenant 权限：`im:message:send_as_bot`、`im:resource`、`im:chat:read`、`im:chat.members:read`，并预填 `card.action.trigger` 回调。用户仍需在飞书后台确认机器人能力、可用范围和应用发布，将机器人加入目标群；注册成功不代表这些权限已生效。

选择群及允许操作的本人账号后，引导启动本机长连接。进入“事件与回调 → **回调配置**”，选择长连接，确认“卡片回传交互”，保存并发布新版本。然后按引导发送一张合成测试卡片和小文本附件，点击按钮；程序查到真实回调才算验证完成。测试不写正式待办。

卡片已发送但回调没收到时，重新运行引导会等待原测试卡片，不自动重复发送。发送结果未知时应先核对群和本地测试记录；不要靠反复创建测试卡片绕过未知状态。完整后台操作见 [飞书配置](feishu-setup.md)。

## 一键启动与登录启动

| 入口 | 行为 |
|---|---|
| `Start.cmd` | 隐藏启动独立自动化服务和调试台，确认服务状态后打开页面；重复启动复用已有进程 |
| `Configure.cmd` | 继续未完成引导；完成后可调整模型、配置登录启动或启动服务 |
| 面板 → 自动处理 · 后台运行 → 开机自启 | 读取 Windows 实际启动项，开启/关闭当前安装的登录启动 |
| `tools/automation/stop.cmd` | 请求安全停止自动化，等待正在执行的任务完成；不杀微信或 QQ |

开机自启使用当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，条目名为 `ChatCollector-<安装目录摘要>`，只在该用户登录后运行，无需管理员权限或保存 Windows 密码。它调用同一个隐藏启动器，**不自动打开浏览器**。关闭启动项不停止当前服务；已在任务管理器禁用的条目会显示为禁用，明确点击开启后才恢复。权限不足、查询失败会明确报错，不伪装成“未开启”或“已保存”。

后台包含已配置的采集、模型处理、消息投递、状态回写和飞书监听；各项是否执行仍由配置开关决定。调试台自身的采集定时器默认关闭，避免和独立自动化重复调度。机器关机/休眠或用户未登录时不执行任务。

启动失败时查看 `data/install/launch-status.json`，或重新运行 `Configure.cmd`。端口被其他程序占用时不会接管或终止对方；修改 `tools/console/console.toml` 的 `port` 后再启动。

## 安装包与升级边界

- 包中不含 `.env`、`secrets`、聊天数据库、导出消息、账号配置、现有回执或其他本机用户数据；初始配置使用单独的去身份化模板。
- 本次是联网安装包，不是离线安装器。下载包校验失败、断网或依赖失败会停止，可再次运行安装目录中的 `Install.cmd`。固定下载源内容改变时需由维护者更新版本/校验值，不能跳过校验。
- 此版本不提供覆盖升级、数据迁移或自动卸载数据。备份 `.env`、`config`、`secrets`、`data` 后再规划迁移。更换安装目录前应关闭旧目录的登录启动项。
- 私有 Python 使用安装时写入的绝对模块路径。手动移动目录后需重新运行新目录的 `Install.cmd` 修复运行路径，并核对配置中的绝对路径；不会自动迁移数据位置或旧启动项。
- 该包供当前用户本地验收。已有微信来源文件的授权记录未证明公开再分发许可，发布公共下载前还需核实上游许可；不将“本地可打包”等同于已完成公开发行审查。
- 模型处理会把选中消息及实际读取的附件发到用户配置的接口；启用飞书后正式待办与材料会离开本机。首次 7 日处理可能比日常增量耗时、耗费更多额度。

构建入口：`python tools/install/build_release.py`。默认产物在 `dist/`，附 `.zip.sha256`；包内 `release-manifest.json` 保存源码提交、构建时是否有未提交修改、文件清单及各文件 SHA-256。验收结果见 [安装验收](installation-acceptance.md)。
