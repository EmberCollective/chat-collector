# 通道配置与合成测试

`messaging.management` 是消息层公开的本地管理入口，调试台只是调用方。配置保存不发送消息、不启动监听、不处理待办；调度服务下一轮读取最新配置，长连接的应用凭据或目标变更需要由管理进程重启相应监听。

| 函数 | 用途 |
| --- | --- |
| `read_settings(path)` | 读取版本号和可编辑字段，不返回密钥值或内部路径 |
| `save_settings(path, payload, expected_version)` | 校验并原子保存，配置版本过期时拒绝覆盖 |
| `send_test(path, target_id)` | 向已经启用的目标发送一轮明确标注的合成测试 |
| `test_history(path, limit=20)` | 查看测试发送结果和飞书按钮回调结果 |

配置返回 `version`、`enabled`、`feedback_enabled`、`targets`、`schemas`、`schedule`、`reminders`、`feedback`。保存时剔除只读 `version` 和 `schemas`，把 `version` 作为 `expected_version` 传入。按目标 `id` 合并；未提交的目标与未知字段保留。停用目标使用 `enabled=false`；更换通道种类需要新增目标 ID，避免沿用不兼容回执。

`schemas` 按通道给出字段白名单及类型：`env` 是环境变量名称，不是凭据内容；`strings` 是字符串数组；`properties` 是 Notion 属性名映射。`schedule` 允许扫描间隔、重试间隔、最大尝试次数与单轮数量，`reminders` 允许 P0–P4 间隔，`feedback` 允许重试间隔与最大尝试次数。凭据继续由本机 `.env` 或环境变量维护。

保存采用进程间锁、内容版本校验、临时文件完整校验和原子替换。校验或替换失败时原配置保留。手工编辑应避免与面板保存同时进行；检测到外部变化会要求重新加载。

测试必须同时启用消息层和目标。每次明确点击都会产生一个新测试 ID；测试不会创建处理层待办，也不会进入正式投递提醒队列。飞书应用机器人发送合成卡片和小文本文件；配置关闭附件上传时按实际配置仅发送卡片。其他通道使用自身已有能力：Webhook 输出材料索引，普通飞书机器人不上传文件，Notion 创建明确标注的合成条目。

飞书测试按钮经过与正式卡片相同的应用、群、消息、操作者和 token 校验，仅写测试点击记录并提示“测试回调成功，未修改正式待办”。真实反馈队列不会收到测试操作。发送记录位于消息状态库同目录的 `tests/`，按钮记录位于专用反馈库的 `feishu_tests` 表；小文本保存在消息附件目录的 `synthetic/`。测试超时记录为结果未知，不自动重发；先查看目标平台再决定是否再次发起测试。
