## 探针开销与归属边界

所有窗口共用最多每 5 秒一次采样。根据用户后续要求，探针改为随控制台启动，由一个后台线程持续记录；关闭浏览器、切换页面或失去焦点不停止采样。浏览器仍仅在概览可见时读取已有结果。最近 60 秒最多 13 点留在内存，不落库、不扫描所有系统进程或持续追栈。服务首次启动或采样中断超过 15 秒重新建立计数基线，下一次采样才有有效速率；首次打开网页可直接读取服务已有采样。

Windows 使用原生 PDH 物理盘空闲时间计算繁忙度，并读取物理盘读写吞吐；设备属性识别 HDD／SSD，不启动 PowerShell 采集辅助进程。已核验的业务后台、监听、手动任务及 Pi 子进程按身份和父子关系去重，未知或不可读取用空值表示。读取自动化 SQLite 使用只读连接，锁等待最多 150 毫秒。

共享后台中的采集、处理、投递、回写无法仅靠进程探针准确分摊；不以当前任务名推断独占资源。进程 I/O 包含缓存和其他磁盘，不能与上方物理盘速度直接对账。短于采样间隔的任务可能漏采，图中最高点不是精确峰值。实时任务上下文跟随采样保存，历史悬停不会拿当前任务代替当时任务。

本机真实 GUI 检查记录的一次采样耗时为 24.47 毫秒。这是单次观测，不是低配机器或长期运行的开销保证。

## 首页性能调整

主要等待来自隐藏页面初始化：原首页先连续两次扫描 Pi 历史并解析不相关的任务结果，之后才请求概览。原主页一次导航有 24 个 API 请求，本次减少至 4 个：会话、来源目录、概览、负载；首次负载等待基线时会在 5 秒后增加一次负载请求。

- 会话读取共用；来源配置、待办处理、Pi 和自动化表单进入对应页面后才初始化，保留通用详情事件。
- Pi 列表先用 `job.json` 判断模块／操作，再读取相关结果；首次选择与进入页面不再重复请求列表。
- 服务启动时异步预热概览。服务器共用最多 4 个时间窗口的快照，最长复用 5 秒；配置、任务记录、内存任务及 SQLite 主文件／WAL／SHM 版本参与失效判断，成功写操作清除快照。
- 历史摘要缓存最多 4096 项，投影 JSON 序列化负载上限 2 MiB。该上限不等于 Python 整个缓存的驻留内存；缓存不保留聊天正文或模型上下文。历史详情仍按需读取。
- 快照记录扫描开始时的版本，防止扫描期间写入被错误标记为已更新；多个请求共用重建锁。尝试次数按模块批量查询，移除逐轮查询。
- 概览每 30 秒、负载每 5 秒可见时更新，隐藏页面不持续轮询。认证 API 继续使用浏览器 `no-store`。

本轮未新增数据库索引。现有时间索引及尝试表主键可服务当前查询，实测主要瓶颈是串行请求和 JSON 重复解析；加索引不能解决这些等待。审批前证据保留于 [性能定位报告](PERFORMANCE-PLAN.md)。

## 后续修正：持续采样与当前执行

用户反馈前台才采样无法回看切页期间的负载，以及系统卡片难以识别正在执行的来源。已改为控制台生命周期内持续采样；重复启动不创建多个采样线程，采样失败按正常间隔重试，退出时唤醒并停止线程、释放计数器。仍只保留原有 60 秒内存窗口。

运行行突出来源与“执行中”，列出实际开始时刻和每秒更新的已运行时长，点击来源可进入该模块的执行中记录。每 5 秒的既有采样包含核验后的任务上下文，用它更新运行状态；开始／结束时重新读取概览和下次计划，秒数在浏览器本地递增，不每秒读取数据库或重绘图表。超过 15 秒未核验的运行状态显示待刷新；手动任务在定时后台停止或计划关闭时仍可显示真实执行状态。

新增自动检查覆盖无 HTTP 请求时继续采样、重复启动、退出释放、失败重试间隔；浏览器检查覆盖 QQ → 微信 → 空闲的自动切换、结束后计划恢复、每秒计时不额外读历史、当前记录跳转与手动任务。真实部署及后续检查证据单列于 `.runtime/runtime-monitoring-followup/`，不覆盖首次部署的测量记录。
