## 已对齐的布局

- 桌面侧栏 224px、顶栏 64px，窄屏顶栏 56px；页面边距、分类标签和状态条沿用批准稿。
- 自动化三个分类的状态条、标签、主面板起点与宽度，在两个尺寸下误差均小于 1px，由截图脚本断言。
- 采集与处理主面板：桌面高 511.3px、窄屏高 716.5px，与批准稿误差小于 1px；桌面整页高度均为 1023px。
- 桌面后台服务主面板高 293.4px，与批准稿一致；窄屏分别为批准稿 631.5px、实现 629.9px。真实启动项状态会改变文字与内容高度。

为了比较相同数量的内容，视觉检查只在浏览器内提供合成概览响应，并将自动化 GET 响应对齐到三个来源、三个目标的示例场景；真实来源编号保留，不修改服务配置。运行状态、启动项支持和操作文案仍按实现语义展示。功能检查另外运行真实合成接口，覆盖额外来源、未知渠道、配置保存和错误恢复。

## 保留的功能差异及原因

- 正式页面显示真实连接与后台状态，移除“设计预览”文案；示例数值不会进入正式实现。
- 高级设置保留原有重试、限额、失败通知、早报等配置，折叠入口贴近所属模块，避免占据常规设置区域。
- 到期提醒与消息投递共用已有计划，页面明确说明；未照着示例另建重复调度器。提醒方式选择器直接修改现有截止提醒开关。
- 监听的频率表示检查进程是否存活，不冒充渠道轮询频率。缺失能力或系统不支持时如实显示，并保持不可用操作不能执行。
- 服务状态可展开真实任务检查；操作反馈仅在操作后出现。错误详情和保存后的返回保留原来源与筛选条件。

## 复跑

先启动只使用临时数据、拒绝真实服务启动及外部发送的预览：

```powershell
python -B tools/console/tests/ui_fixture.py --port 18451
```

另一个终端设置已安装的 Playwright 路径，然后运行：

```powershell
$env:PLAYWRIGHT_MODULE = '实际安装位置的 playwright'
$env:CONSOLE_TEST_URL = 'http://127.0.0.1:18451'
$env:DESIGN_PARITY_MATCH_APPROVED = '1'
$env:DESIGN_PARITY_OUTPUT = '.runtime/design-parity-final'
node tools/console/tests/verify-design.cjs
```

输出包含每页的批准稿、实现页、放大差异图及 `report.json`。设置 `DESIGN_PARITY_LIVE_OVERVIEW=1` 并取消 `DESIGN_PARITY_MATCH_APPROVED`，可另存未经响应替换的合成接口截图。全页尺寸不同则标记不可逐像素比较，不计算百分比。
