# 逐项投递计划与每日早报：实现验收

2026-11-15，在 `codex/console-redesign`、基线 `edf217c` 的工作区实现用户批准的 [参考稿](index.html)。本地原有自动化、消息和控制台配置修改保留，未更改启用状态或提醒频率。未提交或推送本轮变更。

## 交付行为

- “行动与投递”进入即加载真实待办，不再先点预览；保留批准稿的两个页签、列表、筛选、详情、规则说明及早报正文布局。
- 列表显示截止时间、下一次预计开始时间、倒计时和原因；每个投递目标独立显示状态与最近成功时间。目标关闭、后台停止/状态未知、失败、结果未知和反馈待回写分别说明，不承诺送达时间。
- 搜索按标题、待办编号、来源；支持状态与目标筛选，每页 50 项及前后翻页。仅日期截止按任务时区补足，展示上海时间并标记补足来源。
- 早报按日期、通知型目标预览当天已知安排，显示规则时刻、时区和补发窗口。未发送内容按最新状态预估；已发送、结果未知和发送中的记录展示当次正文快照，避免用当前待办改写历史。
- 材料与原文在单项详情按需加载，保留下载、来源、行动步骤、参与人员与材料警告。完成/延后/恢复通过原状态接口执行；反馈入队不显示成已回写。异常可进入既有投递与回写恢复区。

## 数据与职责

| 入口 | 用途 / 边界 |
| --- | --- |
| `GET /api/messaging/schedule` | 已发布待办、消息层本地状态及投递记录的只读组合；支持 `limit` 1–200、`offset` 0–200000、`search` 最长 500 字、`state`、`target_id` |
| `GET /api/messaging/digest` | `date=YYYY-MM-DD` 与通知目标 `target_id`；支持最近 31 天、未来 366 天；实际正文快照和内容预估分别标记 |
| `GET /api/messaging/tasks/{task_id}` | 单条行动、材料、原文及该待办投递计划；不导入、不发送 |
| 原有写入入口 | 保留本地同步、任务状态请求及人工投递核对；浏览页面不会自动调用 |

接口复用本机来源检查与 `X-Console-Token`，不返回渠道凭据或目标配置中的环境变量值。目标名称、能力和通知/同步模式来自后端描述，不在前端按平台或目标编号分支。

实际发送与预览共用 `messaging.notifications.reminder_due`、`digest_items`。已有队列仍负责幂等、覆盖节点、重试和未知结果保护；未新增数据库、表、索引、任务契约或发送方式。规则计划不等于投递队列，未来早报预估也不创建队列记录。

列表读取待办及必要投递元数据，不调用材料整理/哈希校验；只有打开单项详情才构建材料包。列表每 15 秒在可见页面读取一次，倒计时在本地每秒更新；无变化时保留行 DOM。原后台调度继续独立运行，浏览器关闭不影响投递。

材料是否变化最终由后台下一轮完整检查确定。独立消息进程没有可确认的自动化进程记录时，面板显示状态未确认，不据检查频率编造实际开始时间。早报对某目标未知回执的筛选继续遵循已有实现，没有额外改变业务发送范围。
