# 运行概览扩展设计预览

打开 [统一运行概览](../console-redesign/index.html#overview)。本目录的 [旧入口](index.html) 自动跳转至同一页，主稿不再维护另一套概览；批准后的正式源码已实现同一布局，见 [实现记录](../console-redesign/IMPLEMENTATION.md)；本文件仍为独立静态基线。全部数字为固定示例，不连接后台。可切换概览演示场景，并从错误入口打开具体运行详情。

优先级：**当前错误与待确认 → 系统是否持续工作 → 采集质量与产出 → 历史排查**。借鉴用户提供的报告表格和成功率色条，保留拾序原有名称、Logo、字体与品牌绿。没有复制参考报告中的业务数据或脚本。

| 选择的参数 | 用户能据此判断什么 | 口径 |
|---|---|---|
| 当前待处理问题，区分失败 / 结果未知 | 现在是否需要介入，应该先做什么 | 合并同一未恢复问题，显示最后发生、影响与下一步；未知投递先核对，不直接重发 |
| 服务实际状态、启用任务状态、当前工作与最后成功时间 | 页面能连接时，后台是否真的在完成工作 | 区分运行中、等待、退避、主动暂停和状态未确认；仅配置启用不等于正常 |
| 采集入库变更条数、重复跳过条数 | 实际产出多少，是否一直没有新结果 | 正式采集 emitted 与 duplicates；emitted 包含新增及修订，不能称为独立消息数 |
| 采集平均耗时、P95 与样本数 | 一般要等多久，慢轮次是否变多 | 有效已结束正式采集的墙钟耗时；P95 采用最近秩，含启动、刷新、筛选与附件处理 |
| 成功率、分时趋势与最近 20 次结果 | 故障是偶发还是持续，集中在哪个来源 | 成功 /（成功 + 失败）；同时显示分子分母。等待刷新、无新时间窗、无启用规则、执行中和结果未知不混入成功 |
| 处理积压与投递 / 回写待确认 | 上游完成后，后续步骤是否卡住 | 分别保留组、条、项等实际单位；尚未计算显示未计算，不能填 0 |

每个统计使用相同的时间范围、操作范围与来源实例 ID，名称只是显示信息。不同来源和渠道只展示其实际提供的统计，外部来源未提供指标时显示“未提供统计”。成功率色条是最近 20 次有效轮次，旁边百分比是整个时间窗，已分别标清。图表纵轴固定 0–100%；无样本时留空，不能显示 100%。

不选择 TPS、首 Token 延迟作为首页指标：它们主要描述模型服务吞吐，不直接回答消息是否采集成功、系统是否卡住。CPU / 内存也暂不放首页：目前没有相应采样，资源占用不能代替任务健康。未来出现有证据的性能排查需求时，可放入诊断详情。

正式接入将基于已合并的后台轮次记录实现指标聚合，仍需补齐已恢复故障的持久化关联及投递 / 回写的独立结果口径。不能只用当前控制台最近 30 条任务推算全系统成功率，也不再另建一套调度或执行记录。实现之前先确认这份首页布局与指标。

内部检查：正常 / 异常 / 无数据场景、相关运行对话框、320–1600px 页面无横向溢出、公式与分母一致、无脚本错误、无 HTTP 请求。尚未做真实用户测试和实际指标接入。

## 来源占比与资源占用

加入可切换的环形图（饼图的变体），旁边同一张来源表始终同时呈现消息数量 / 比例和空间大小 / 比例，便于直接对照，不用记住另一张图的数值。

- **消息贡献**：所选时间窗内已提供统计的入库变更条数，体现规模，不等同于信息价值。未统计来源标记未知，不当作 0。
- **存储占用**：当前项目文件的空间快照，包含状态库、明文快照、消息批次及附件归档，不等同于整盘使用率，也不与 24 小时消息量混用分母。
- **资源归属**：按来源实例归属，同一文件不能重复计算。跨来源共用目录或文件单列“共享 / 未归属”，不随意平分。
- **实测边界**：空间目前为演示值。正式接入需区分文件逻辑大小和磁盘实际分配空间，处理硬链接、目录重叠、缺失路径与读取失败，显示实际覆盖范围。未测出的空间不能补 0。

没有用消息条数除以空间生成“价值评分”：时间范围不同，附件大小也不代表价值。要衡量效率，应先统一时间窗，再定义有效新增产出。

## 错误下钻与安全恢复

顶部问题、成功率折线的失败点、最近 20 次失败色条、系统状态的问题按钮与来源问题计数，统一打开对应范围的示例运行。详情包含操作、模块、触发、开始时间、耗时、结果、错误、上下文和折叠日志，并提供相关配置入口；“返回相关运行”保留来源、时间范围与结果筛选。折线失败点和色条可用键盘操作。

投递结果未知时，详情先给核对目标、内容与时间；勾选已核实后才可演示“已收到”或“核实未达后重试”。前者更新示例为人工确认送达；后者只进入等待重试状态。采集失败可演示安排新一轮，原失败与历史成功率仍保留，不能把安排或排队当成完成。处理后不再提示重复人工操作，但记录继续展示实际示例状态。

概览、自动化、行动投递与运行记录现共用主原型。相关配置按实例 ID 选择来源，投递配置进入自动化的投递与提醒；“返回刚才的运行”保留原详情与范围。运行记录沿用相同示例目录，概览与行动投递共用核实结果。

所有运行是少量代表性示例，不是最近 20 轮的真实完整目录。演示只改本页内存，不执行采集、保存、重试或投递；刷新恢复初始状态。新增内部检查覆盖五类错误入口、详情字段、筛选与返回、未知结果的两种安全恢复、重复提交阻止、原历史指标保留，以及窄屏和键盘；无 HTTP 请求或脚本错误。[查看恢复详情截图](previews/run-detail.png)。未验证真实日志、跨页面持久化、服务配置或外部送达。

## 维护与场景边界

`source/overview.html`、`source/overview.css`、`source/overview.js` 是唯一概览维护源；脚本使用闭包隔离，在主稿中复用来源目录、导航和投递状态。无 iframe、服务器或新增依赖。

```powershell
node docs/design/overview-dashboard/build.cjs
node docs/design/overview-dashboard/build.cjs --check
```

构建将片段嵌入主稿的明确标记中，生成后仍可双击单个主 HTML 浏览。“概览演示场景”只影响本页指标；正常 / 空数据时有可见范围提示，其他页保留原始记录及已核实结果。自动化开关属于草稿，示例服务启用数取已确认初值，不随未写入的草稿或演示保存改变。

新增内部检查覆盖生成一致性、主导航内切换、配置按来源选择、跨配置 / 历史返回、两方向投递核实同步、未知来源不补统计、草稿不冒充运行事实，以及场景切换不覆盖核实结果。检查仍限静态浏览器，未连接正式服务、读取真实文件或验证真实用户操作。
