# 文档维护规则

本文件适用于 `docs/` 及其子目录的新增、修改和迁移。动笔前先读 [文档索引](README.md) 和相关主题的现有文档，核对实际代码入口，优先更新已有页面。

## 目录归属

按职责归档，安装、架构和设计记录单独保留。`docs/` 顶层只保留总索引、本文件和分类目录，不再散放业务文档。

| 目录 | 应放内容 |
| --- | --- |
| `collector/acquisition/` | 收集层／采集：来源捕获、快照发布、增量刷新、快速数据库查询的操作方法、索引排查与采集性能实测 |
| `collector/compatibility/` | 收集层／兼容层：提供方接入、平台字段适配、标准 SQL 查询实现、身份资料、附件定位与读取 |
| `processor/` | 处理层：采集输入契约、处理配置、AI 输入、处理输出契约、任务查询与状态接口 |
| `processor/pi/` | 处理层／Pi 组件：运行时、工具、上下文、压缩、重试和完整工作流记录 |
| `information/dispatch/` | 信息层／信息调度：任务变更消费、通知与提醒、投递和反馈队列、调度契约、自动运行与恢复 |
| `information/channels/` | 信息层／渠道：渠道配置、凭据与权限设置、呈现、上传、回执、平台回调及新渠道开发 |
| `architecture/` | 跨层职责、依赖、数据所有权、公共边界和带明确基线的架构实施记录 |
| `guides/` | 安装、启动、源码开发与安装验收等跨层操作指南 |
| `design/<主题>/` | 静态设计稿、设计依据、预览资源与对应验收记录 |
| `examples/` | 文档引用的合成数据与协议样例，不含真实聊天、附件、账号或凭据 |

归档时遵守以下边界：

- 快速查询的使用方法放在采集目录，实现说明放在兼容层；复用现有 [查询指南](collector/acquisition/fast-query.md) 和 [实现说明](collector/compatibility/query-implementation.md)，不另建同义文档或查询 API。
- 采集输入和处理输出契约分别维护在 [input-contract.md](processor/input-contract.md)、[output-contract.md](processor/output-contract.md)；信息调度契约维护在 [dispatch/contract.md](information/dispatch/contract.md)。其他页面引用权威定义，不复制整份字段表。
- 文档分类不改变代码所有权：`collector` 管采集快照，`providers` 管兼容查询与内容，`selection` 管筛选与发布，`processor` 管任务，`messaging` 管交付，渠道管平台呈现与回执。`automation` 跨层调度，文档归调度目录，不据此搬动代码。
- 性能研究跟随被研究模块归档，例如 QQ 快照研究放在采集目录；界面设计与布局验收放在设计目录。跨层说明选择一个主要归属，再从其他入口链接。

## 页面与导航

1. 文件名使用有意义的英文小写短横线命名；目录入口使用 `README.md`，本规则文件使用 `AGENTS.md`。已有设计资料不为统一大小写而批量重命名。
2. `docs/README.md` 维护三层导航和常用任务入口；分类 `README.md` 只解释该目录职责并链接具体文档，不复制正文。
3. 新增页面必须接入最近的分类索引；新增分类或关键入口同时更新总索引。不要留下只能靠搜索文件名才能找到的页面。
4. 使用相对链接连接仓库文档、代码和示例，链接文字说明目标内容。引用具体小节时核对锚点，不使用本机绝对路径或临时运行目录作为公共入口。
5. 移动或重命名时同步修正出站链接、入站链接、根 README 和其他目录中的引用。默认直接迁移，不保留重复正文或空跳转页；确有兼容需求时说明保留理由。

## 内容怎么写

以中文说明用户或维护者要完成的具体任务；模块名、接口名和字段名保留代码原名。开头直接交代本页用途和必要前提，重要结论在前，细节随后。标题要能独立说明内容，删除空话、重复总结和没有内容的章节。

按页面用途选择必要内容，不给所有页面强套同一模板：

| 页面用途 | 必须说清楚 |
| --- | --- |
| 操作指南 | 前提、工作目录与环境、最短操作、预期结果，以及常见失败的恢复入口；区分只读、写入、模型调用和外部发送 |
| 接口或数据契约 | 版本、输入输出、字段类型与约束、时间单位和时区、窗口边界、错误、幂等与兼容要求；链接对应实现和验证依据 |
| 实现说明 | 实际调用链、职责归属、关键取舍、资源释放、一致性与缓存失效条件；不逐行翻译代码 |
| 性能或验收记录 | 日期、源码或产物基线、环境与样本、测量方法、结果、结论和未测范围；明确是否真实账户、模拟数据或静态稿 |

同一事实只维护一个权威来源。操作示例可以复述必要条件，但不能平行维护多套契约、字段定义或默认配置。比较用表格，多步骤或跨模块关系需要图时用 Mermaid；不为装饰添加图表。

区分已实现行为、设计目标和历史记录。未实现的功能明确标注；历史记录保留当时基线，不把旧状态写成当前状态。代码与契约不一致时记录具体差异，不通过改写文档掩盖问题。新增来源和渠道使用既有注册入口，不在示例中宣称必须修改处理核心或硬编码平台分支。

## 示例、查询与证据

- 示例使用合成数据、占位凭据和配置相对路径。不得提交真实数据库、聊天正文、私人附件、密钥、令牌或本机账号路径；截图和日志也适用。
- 命令说明工作目录、必要依赖和参数。标为可直接运行的示例须包含必要准备，并实际验证；片段须说明所依赖的变量，不能标为完整脚本。
- 数据库诊断默认只读，复用已发布快照、标准查询入口和既有锁。查询值使用绑定参数；动态表名只从允许集合选择。说明时间窗、条数上限、分页和快照变化后的处理。
- 索引建议必须有查询条件与实际计划依据。原始库只读，微信对齐镜像和 QQ 私有增量镜像不得添加业务索引；独立自有查询库另按计划评估。不要把规则 `LIMIT` 写成能减少来源扫描。
- 不为验证文档自动刷新来源、推进断点、调用付费模型、发送通知或改变真实账号设置。需要这些副作用的操作应在步骤前明确说明，并按已有授权执行。
- 性能数据区分冷读、热缓存、有变化和无变化轮次；不能将不同样本直接称作倍数提速，不能将阶段耗时或合成结果当成真实整轮结论。

## 完成前检查

1. 核对目录归属、索引入口，以及所有受影响的文件链接和小节锚点；确认没有同义重复页面。
2. 核对示例中的命令、配置键、接口和返回值与实际实现一致。新增或修改可执行示例时，用临时合成数据验证关键边界，不拿真实账号做默认测试。
3. 检查 Markdown 排版与 `git diff --check`。纯文档改动无需重复运行整套业务测试；行为或接口也改变时执行对应检查。
4. 交付说明准确区分通过、失败和未测，不以测试数量替代适用范围，不把静态预览称为真实运行验收。
