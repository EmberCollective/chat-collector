# 架构重构：Agent 分工与验收

本文件与 [目标架构](architecture.md) 配套，固定任务分工和禁止偏移的边界。用户已批准候选实施；进展与实际入口见 [候选实现与迁移](architecture-implementation.md)。后续任务仍按依赖分阶段派发，不让每个 Agent 各自重构整条链路。

## 每个 Agent 必须先读

1. [目标架构](architecture.md) 的 B01–B13、数据所有权、相关接口和最终验收。
2. 本文自己的任务卡及其前置任务交付。
3. 涉及文件的当前代码、调用方、配置和测试；记录当前 Git SHA、已有未提交修改和自己的文件范围。

用户要求是最终边界：SQL 适配与执行在兼容层，Pi 工具通过兼容接口索取内容。任何 Agent 都无权以实现方便为理由改变这两条。

## 分工规则

子 Agent 的模型配置由用户明确指定，所有实施、审查和验收子任务均须使用：

```json
{"model": "gpt-6.1-sol", "reasoning_effort": "high", "fork_turns": "none"}
```

不得选择 `gpt-6-astra`，也不得静默降级或提高思考强度。当前派发工具要求显式指定模型/强度时使用 `fork_turns="none"`，因此主 Agent 必须在任务消息中提供工作目录、文档路径、任务编号、文件范围、前置交付和必要上下文，不能假设子 Agent 会继承聊天历史。旧 Agent 若不是该配置，不直接复用；模型不可用时报告阻塞并继续可独立完成的工作，不擅自换模型。本要求不改变现有主 Agent 的运行配置。

- 只修改被分配的文件；公共接口、共用测试夹具和配置结构由指定负责人维护。需要跨范围修改，先向主 Agent说明原因和最小改动，不能自行覆盖另一人的工作。
- 不新建服务框架、消息中间件、模型循环、规则语言或独立面板项目。不得复制一套旧实现后长期保留两套业务真相。
- 不修改真实账号、密钥、正式任务和生产开关；不运行真实模型、取钥、发通知或批量补发。相关联调由集成负责人按已有用户授权单独执行。
- 原 CLI、配置和调用兼容通过薄包装保持。包装只转发，不能长期执行第二套筛选、解码或持久化逻辑。
- 已有未提交内容不属于本任务的，不清理、不重置、不混入提交。主 Agent统一协调分步提交与集成。
- 不把“本地测试通过”报告为“真实账号已验收”；每项标明模拟、真实、未测或阻塞。
- 边界冲突先交主 Agent；与用户设定冲突的方案不得实施。日常内部实现选择不需要反复向用户申请批准。

## 派发顺序

| 阶段 | 任务 | 前置条件 | 可并行范围 |
|---|---|---|---|
| 0 | A0 契约与迁移基线 | 主 Agent确认本次实施范围 | 先单独冻结接口 |
| 1 | A1 收集边界；A4 待办服务 | A0 | 两者可并行，不共用业务文件 |
| 2 | A2 兼容查询与内容 | A1 来源快照接口；A0 | 可与 A4 并行，不与 A1 同改 adapters |
| 3 | A3 SQL 筛选；A5 Pi 接入；A7 渠道 | A2/A4 对应接口已冻结 | 可分文件并行，不能自行改公共契约 |
| 4 | A6 消息编排与实时唤醒 | A4、A7；A0 操作/信号契约 | 渠道交付后完成反馈与发送集成 |
| 5 | A8 迁移、回归与安装交付 | A1–A7 | 集中验收，不同时重构接口 |

任务多于可用 Agent 槽位时分批派发。接口未交付时可用契约测试替身开发，不得猜测接口后把猜测写入另一模块。

## A0：契约与迁移基线

**负责人：主 Agent 或明确指定的契约 Agent。**

拥有：`contracts.py`、目标公共契约、必要的 `common/`、架构文档和公共测试夹具。

交付：

1. 记录源码版本、脏工作区清单、数据库 schema 和备份/恢复办法；不把凭据写入报告。
2. 固化来源快照、SQL 查询、附件内容、待办 API、变更流、标准操作、投递与回执的最小契约。
3. 给出旧接口与目标接口映射、合成第三平台及两个不同 schema 的测试夹具。
4. 提取锁、稳定序列化、摘要等公共函数，保留旧导入包装；不把业务搬到 common。
5. 给各 Agent 实际允许修改的文件清单，冻结共享文件的交接顺序。

验收：契约模块导入不访问数据库、不启动线程或服务、不加载模型/平台 SDK；旧事件样本可读，未知版本和无效身份明确失败。

禁止：强换事件主版本、重生成已有 ID、引入通用 ORM 或远程服务框架。

## A1：收集层只负责获取与入库

拥有：`collector/adapters/qq.py`、`wechat.py` 的刷新/快照部分，原生增量模块、收集入口和配置。平台读取函数拆分须与 A2 顺序交接。

交付：

1. 提供独立采集行为和已验证快照/原始资料契约，不依赖规则、Pi 或消息配置。
2. 分离收集与筛选进度；刷新只更新收集状态。
3. 复用原生引擎与增量校验，失败保留好库、可清理临时文件；第一次之外不退化为整库导出。
4. 明确快照生命周期、并发读取/发布方式及原库变化的重试语义。
5. 原 `collector once/run` 的复合行为交由应用编排兼容入口维持；collector 核心不能 import selection。

验收：无启用规则仍可采集；QQ WAL 追加/重写、微信快照、失败回滚和临时文件清理通过固定样本测试；采集故障不阻断已发布消息处理。

禁止：改写原生密码算法、启动模型、因筛选失败清空数据库、在收集器内判断关键词或优先级。

## A2：兼容层拥有 SQL 和附件适配

拥有：`providers/`；从 `collector/filters.py` 接收的查询环境/执行代码；平台消息/身份映射和 `collector/attachment_provider.py` 的平台实现。`collector/assets.py` 中需复用的部分按 A1 交接归置，不复制引擎。

交付：

1. 实现 `query_rules(scope, window, rules)`：固定快照、字段映射、标准 SQLite 表/视图、参数绑定、只读执行及输出验证。
2. 临时库创建、填充、索引、连接、authorizer 和清理全部在兼容层。返回标准消息及各规则命中身份，不自行选择规则。
3. 提供有限历史、稳定时序、前驱事实、完整触发消息和附件索引；不跨群取上下文。
4. 补齐账号、会话、昵称、备注、群昵称、缺失标记和资料来源；人物只含上下文涉及的人。
5. 实现 `read_attachment/export_attachment`，内部处理归档验证、按需定位/准备/原生解码/解析及缓存。
6. 返回与 Pi 无关的内容/证据结构，保留文件名和格式；取消、资源限制、明确失败和隐藏进程行为保留。
7. 提供合成第三平台，证明接入新来源不改筛选、Pi、消息核心。

验收：两个不同 schema 执行同一 SQL 得到一致语义；查询不能写库；params 无逐项适配；仅引用附件可按需准备，已有归档不重复解码，缺文件明确失败。

禁止：把适配表交筛选层执行、要求所有原库统一 schema、让工具端解析 PDF、根据附件正文执行代码、增加未授权网络下载。

## A3：SQL 筛选只拥有策略与发布

拥有：目标 `selection/`、规则注册/合并/断点逻辑、`rulesets/` 兼容测试；从 `collector/store.py` 接收筛选事件发布职责。原始采集状态不得整库迁移或删除。

交付：

1. 加载注册的 SQL、参数和上下文条数，调用 A2；不直接连接消息查询库，筛选自己的状态库不受此限制。
2. 合并同窗命中，保留全部 `matched_rules`；所有规则成功才提交窗口。
3. 保留全员提及、文件、关键词、上下文独立注册；关键词匹配当条，context 默认围绕文件/全员提及前后各五条。
4. 保持事件身份和修订；断点、事件和 outbox 同事务，JSONL 不可变原子发布。
5. 支持独立重放和规则重跑，不能将已被某规则命中作为其他规则的排除条件。

验收：三规则同命中只输出一份并记录三条规则；触发点保留、同秒顺序确定、跨群隔离、重复窗口不重发、发布失败重启不丢；无平台 adapter import 或临时消息表逻辑。

禁止：为每个 params 写分支、新建规则语言、添加用户否定的触发原因字段、偷改现有注册表。

## A4：正式待办服务与变更流

拥有：`processor/actions.py`、`task_search.py`、任务存储/API 模块、`core.py` 中持久化代码与兼容包装。与 A5 划分 `core.py`，禁止同时整文件改写。

交付：

1. 提供 `get_task/search_tasks/create_tasks/apply_extraction/update_task_status/update_task_priority/read_changes/get_material`。
2. Pi、人工和渠道写入均走服务，审计、任务修订、人工控制、幂等记录和 outbox 不拆散。
3. 外部创建有真实 origin 和已验证身份；Pi 仍须引用实际输入/读取证据。
4. 写锁不跨模型、附件或网络操作；模型期间人工可更新，旧模型提交检查版本并保留人工结果。
5. 变更流包装现有发布机制，支持稳定顺序、分页、重放和独立消费者游标，不暴露 SQL 连接。
6. 材料入口校验归属并委托兼容层；不自行解码或解析。

验收：重复请求不增修订、同号异内容拒绝、版本冲突、导出失败补发、模型期间人工更新、完成不复活、级别不覆盖、证据不丢；外部创建不调用模型。

禁止：任意 SQL/字段 patch、消息层直接改表、恢复审核门槛、覆盖历史来源。

## A5：Pi 处理与工具桥接

拥有：`processor/context.py`、`pi_bridge.py`、`pi-runtime/`、上下文投影与模型编排；`core.py` 模型部分在 A4 交接后修改。

交付：

1. 标准消息按会话/连续片段组装，可配置单会话长度，保留多会话批次。
2. `read_attachment` 只校验映射短引用、调用 A2 并包装响应；不直接定位、解码、转码或解析文件。
3. `find_related_tasks` 调 A4 查询；`submit_tasks` 经验证交 A4，不直接写库。
4. 保留 Pi 原生循环、压缩、分页、取消和调试事件；不注入草稿、内部路径或未读正文。
5. 模型提交遵守 A4 版本/人工控制策略，不能重置用户修改。

验收：模拟环境完成“查询 → 按编号读附件 → 提交”；归档缺失时由兼容层准备；未读内容不能成为证据；空结果为 `{"tasks": []}`；任务不混会话；Pi 原生运行时测试通过。

禁止：新写 Agent 循环、插件导入 collector 或文件解析器、强制读完附件、迁移时重跑真实历史模型。

## A6：消息编排、反馈与实时唤醒

拥有：`messaging/core.py`、`notifications.py`、`package.py`、`feedback.py`，`automation/` 调度和 IPC，相关配置及面板既有字段映射。渠道 SDK 文件归 A7。

交付：

1. 经 A4 变更接口更新投影，投影和游标同事务；材料由公开入口获取，消息层只做归档、文件名及投递包。
2. 保持截止节点、首次通知、早报、重试的用户配置值，不借迁移调整默认策略。
3. 入队唤醒反馈，变更发布唤醒对应卡片更新；不提前触发未来提醒，不绕过禁用、退避和 unknown。
4. 复用执行器并提供受控本机 IPC，不依赖面板；信号丢失可补捞，运行中收到信号不丢后续工作。
5. 反馈与发送分别重试；queued、applied 和 sent 不混淆，正式状态只服从 A4。
6. 记录真实链路时刻，修正将轮次开始当发送完成的记录方式；日志不含正文。

验收：正常条件下两段本地唤醒延迟分别 p95 ≤ 1 秒；长模型不阻塞人工更新；面板关闭仍运行；完成停催、改级旧计划淘汰、早报仅今天通知节点；重启、丢信号、并发和退避通过。

禁止：回调线程等待完整业务处理、只缩短全局轮询掩盖问题、唤醒时跑模型、直接写任务表、为补发卡片重做业务修改。

## A7：渠道适配与反向操作

拥有：`messaging/feishu.py`、`channels.py` 的渠道实现和注册、渠道配置字段、SDK 测试。不修改 A6 反馈业务逻辑。

交付：

1. 接收统一信封；修订更新已有对象，提醒不重复创建资料页，早报不创建假任务。
2. 校验平台、目标、操作者、对象映射和卡片代次，转换成标准操作并入队，不直接调用 SQL。
3. 保留完成/恢复及改级；不新增稍后提醒、丢弃或审核按钮。
4. 渠道独立拥有 token/对象/上传缓存；如迁移旧共库，保留有效按钮、消息 ID、代次和回执。
5. 文件名、格式和摘要分离；改名补传后恢复去重，未知结果不能因改名绕过。
6. 返回业务成功回执及错误分类；渠道不自行制定 P0 提醒时间。

验收：卡片/页面更新、伪造与跨群 token、旧代次、双击、错误选项、上传失败、改名、unknown 和远端回声去重。Notion 现有能力保持，未实现的反向监听不能宣称支持。

禁止：新增未批准渠道、读原始聊天库、改正式待办表、toast 冒充应用成功、擅自扩大权限或发测试消息。

## A8：集成、迁移与安装验收

拥有：集成测试、迁移脚本、安装模板、文档索引和验收记录。模块缺陷回派原负责人，不另写旁路。

交付顺序：

1. 检查导入与运行边界：筛选无平台实现、Pi 无解析/解码、渠道不连接任务库、核心无面板依赖。
2. 合成来源跑通收集 → 兼容查询 → 多规则合并 → Pi → 待办 → 消息 → 模拟渠道 → 回写。
3. 在旧库/配置的隔离副本上迁移，核对 ID、修订、断点、人工控制、附件、token、回执和队列。
4. 注入退出、锁冲突、磁盘错误和网络不确定，验证恢复不丢失、不重复修改；旧版本不得读半迁移库。
5. 用最终 ZIP 验证全新安装、继续安装、升级、隐藏启动和面板可选；记录 SHA-256、源码基线与补丁。
6. 真实账号联调按已有授权单列结果，不为凑闭环擅自发送聊天到模型或外部渠道。
7. 更新现状文档；未实现的目标仍标未完成，不用“已解耦”概括部分完成。

验收：架构书最终验收 11 项逐条有证据。禁止删除测试、清空数据或跳过校验来消除失败。

## 任务交付格式

```text
任务编号：
基线：Git SHA + 相关未提交修改说明
拥有并修改的文件：
实现的接口与兼容入口：
数据/schema/配置是否变化及迁移/回退方式：
验证的 Bxx 边界与验收用例：
测试命令、测试层级、实际结果：
未测或阻塞事项：
影响下游 Agent 的接口/行为变化：
是否触及真实模型、外部渠道或正式数据：
```

缺少测试、违反文件所有权、擅改契约或使用跨层旁路的交付不能进入下一阶段。主 Agent 先检查边界再看测试数量；更多测试不能修正职责归属错误。

```text
先读 docs/architecture.md 和 docs/architecture-agent-tasks.md 对应任务卡。
基线与已存在修改：____；允许修改的文件：____；前置交付：____。
目标遵守 B01–B13，特别是 SQL 的适配/临时表/执行归兼容层，
Pi 工具只通过兼容接口索取附件内容，不定位、解码或解析。
不得自行改公共契约、覆盖他人修改、运行真实模型/投递或扩展功能。

交付实现、回归测试、兼容/迁移说明，使用规定交付格式。
完成自己的边界即返回，不接着重构相邻模块。
```
