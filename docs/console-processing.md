# 待办处理调试

调试台通过单向适配调用根目录 processor，采集核心不依赖调试台或模型。页面可在未配置模型时先读取本地规则、预览已采集消息的上下文；不会生成虚构待办。

## 使用顺序

1. 在“从聊天整理待办”点击“预览待处理上下文”，检查实际初始模型输入与本地完整来源。先按群聊/会话组织关联片段，自动模式可合批多个会话且保留边界；模型输入使用短消息/附件引用，完整消息键和来源映射留在本地。最多显示 5 组；候选经过采集 SQL 筛选，不保证原始会话完整。首次启用点只读显示，默认不回扫启用前历史。
2. 在“编辑处理规则”修改本地 Markdown。保存只作用于处理配置指定的文件，最多 1 MiB；旧文件备份到控制台 `.runtime/rules-backups`。
3. 填写 OpenAI 兼容 API 根地址（通常以 `/v1` 结尾）与模型名。密钥在本机环境变量、项目本地 `.env` 或固定密钥文件中配置，页面只填写环境变量名称、显示文件路径，不提供密钥编辑或读取接口。已运行服务看不到之后修改的进程环境变量；本地文件由核心按配置读取。
4. 手动执行一轮。Pi 原生 Agent 使用聊天片段与规则，并按需调用附件工具读取文件文字或图片。读取内容会发给配置的模型服务，是否计费取决于服务提供方。配置支持图片能力开关、Agent 回合上限与工具调用上限（含结果提交）；单会话字符预算为 `context.max_conversation_chars`（默认 20000，范围 1000–1000000），整批预算为 `processing.max_input_chars`。`agent.batching` 可选自动合批或每批单会话。超过整批预算优先按会话拆分，`max_messages` 仅作辅助软限，完整关联片段不按条数硬切；单片段过大明确报错，不静默截断。超时是每批 Agent 的总时间限制。调试台不实现另一套 AI 循环。关闭网页不取消已启动的工作进程。
5. 查看结构化待办、工具活动和来源证据。点击“打开本地原消息与附件”查看对应采集修订，附件下载沿用原有归档路径校验；附件证据可展开页码/位置与归档信息。有歧义的信息标记待核对；未明确的时间、人员或地点保持未知。最近 20 项之外的结果可通过核心输出查看。

模型上下文容量、最大回复量以及压缩预留/最近内容以 tokens 配置；会话与整批输入预算以字符配置，单位不同。上下文压缩及失败重试使用 Pi 原生能力，控制台只保存对应配置并展示压缩次数、重试次数和最大请求字符数。压缩不代表允许截断原始关联片段，初始批次受字符预算约束，后续工具历史由 Pi 按 token 容量原生压缩，不再受逐请求字符拦截。

## 手动调试时间

起止时间默认留空，沿用已保存的首次处理起点和正常增量批次。填写两项后，预览会用**当前注册的 SQL 规则**查询 QQ、微信已解密快照，临时生成分组；不复用历史旧规则的命中结果，也不排除已正式处理的消息。开始时间包含，结束时间不包含；界面使用浏览器本地时间，API 使用 Unix 秒，每次最多 7 天。必要前文可以早于开始时间，标记为历史上下文。

手动预览不修改默认值、采集断点或处理状态，不刷新解密快照、不归档附件、不调用模型。填写时间后可点击“处理所选时间（调试）”：直接用已验证的解密快照、相同时间范围和当前 SQL 查询；附件只提供索引，AI 调用工具时自动准备。调用同一个 Pi 处理流程。SQL、快照或配置在预览后发生变化时，执行输入也会变化。

每次调试独立保存到处理状态库同级的 `debug/<运行编号>/`，包含 `incoming/preview.jsonl`、`state.db`、`todos/*.jsonl` 和 `result.json`。页面在“本次调试结果”展示待办与来源；不写入正式待办，不推进正式采集或处理断点。失败保留输入和已完成结果，重复执行会产生新的调试记录并再次调用模型。一轮仍遵守 `max_groups_per_round`，剩余组数在结果中显示。调试来源保存为本次快照，不冒充采集库中的历史修订。

点击“恢复默认增量”清空两项后，恢复正式增量处理，原默认值不变。手动预览与处理使用浏览器填写的时间，不将其保存为默认起点。

## API

所有接口沿用本机 Host/Origin 检查与 `X-Console-Token` 会话凭证；通过 `/api/session` 获取本次服务凭证。完整结构见本机 `/docs`。

| 接口 | 操作 |
|---|---|
| `GET /api/processor/config` | 读取允许编辑的配置、只读路径及 revision，不返回密钥值 |
| `PATCH /api/processor/config` | 提交 revision 与 patch；校验、备份并保存模型/上下文/间隔/来源描述 |
| `GET /api/processor/rules` | 读取固定 Markdown 文件、正文和 revision |
| `PUT /api/processor/rules` | 提交 revision 与 text；版本冲突返回 409 |
| `GET /api/processor/status` | 轻量处理状态、模型配置状态和已有待办数量；未知待处理数量需显式预览 |
| `GET /api/processor/tasks?limit=20` | 读取最新待办、核对原因和完整来源，排除已被替代的旧结果 |
| `POST /api/processor/preview` | 默认 `{ "limit": 5 }`；手动时间增加 `start`、`end`（Unix 秒，必须同时填写）。返回 202 与异步任务 ID；不调用模型 |
| `POST /api/processor/run` | 不传请求体或 `{}` 执行正式增量；传 `start`、`end` 执行独立调试。调用已配置模型，返回 202 与异步任务 ID；未配置返回 400 |
| `GET /api/jobs/{id}` | 读取运行状态、结果或错误 |
| `GET /api/modules/{module}/source?message_key=…&revision=…` | 查询当前模块采集库中的确切原消息修订，用既有附件接口查看归档 |

配置保存不允许迁移输入、状态库、输出、首次启用点或密钥文件路径。配置备份在 `.runtime/config-backups`。外部处理正在运行、或本面板已有处理任务时，保存与重复触发会返回 409。预览有 120 秒限制；Agent 每批使用配置中的总超时。

## 数据与边界

预览不创建处理数据库，不修改采集批次、不提交消息为已处理，但会创建协调锁文件及控制台任务结果。初始模型输入只包含短引用与必要上下文，工具后续读取的正文或图片不包含在这份初始预览中。完整本地来源折叠显示，不能将其当成发送给模型的内容。附件不可用时显示核心报告的状态，不冒充已读全文。任务结果可能包含聊天明文，和其他本地数据一样应保留在私有目录。

规则变更在下一轮生效。逐组成功结果可被保留，失败组留待重试；失败后应查看任务记录和已有结果。界面不自动运行处理，也不自动发送消息、创建日历或写入其他应用。

调试台的绿色“模型已配置”表示配置项和凭据来源存在，并不代表已经验证网络连接、密钥有效性或模型权限。真实连接只在手动执行时验证。本次调试台测试使用合成消息与模拟结果，没有将真实聊天发送给模型。

“Pi 实时运行与工具调用”区域在执行期间自动更新，显示本机任务的原生 Pi 事件；失败后也保留已发生的调用与压缩记录。任务 API 的 `pi_events` 返回最近 200 个事件，完整事件文件位于该任务目录。这里是嵌入式活动面板，不启动终端窗口。

正式处理只消费已发布的采集批次，采集由各平台单独调度；`input.refresh_collectors` 已停用，旧配置为 true 时仅提示迁移。调试处理只查询现有已验证快照，不隐式刷新、不移动正式采集断点。需要最新数据时先运行对应采集模块。附件工具显式读取时按完整强度准备单个附件，配置文件的日常强度不被改写。

分组附件记录可通过 `GET /api/processor/reviews` 查看，沿用现有认证；页面区分未选读、跳过、部分读取、已读取和读取失败。工具返回失败不再仅显示笼统的“工具返回”；显示可用的错误码，任务本身仍可保存。
