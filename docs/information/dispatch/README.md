# 信息调度层

`messaging` 消费任务变更，建立持久投递与反馈队列，安排首次通知、提醒和重试，再交给渠道发送。完成、恢复、取消和稍后提醒经公开接口回写处理层。

| 需要了解 | 文档 |
| --- | --- |
| 输入输出、投递包与材料生命周期 | [调度契约](contract.md) |
| 定时采集、处理、投递、重试与恢复 | [自动运行](automation.md) |
| 渠道设置、测试与回调 | [渠道层](../channels/README.md) |
| 正式任务操作接口 | [处理层状态 API](../../processor/task-status-api.md) |

`automation` 统一调度采集、筛选、处理和消息任务；打开网页只展示状态，不能作为后台执行的前提。消息调度与渠道开发遵循 [架构的数据所有权](../../architecture/README.md#数据所有权)。
