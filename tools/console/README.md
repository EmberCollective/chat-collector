# Chat Collector Console · 聊天收集调试台

消息收集主项目的可选调试工具，提供简易面板与 OpenAPI。它调用主项目的采集、筛选和去重逻辑，不重复实现解密，也不参与 AI 数据处理。

主项目：`D:\opt\chat-collector`；本工具目录：`tools\console`，不是独立项目。根目录维护采集核心、统一配置和全部业务数据；本目录只维护调试功能及其运行记录。

- 面板：<http://127.0.0.1:10400>
- OpenAPI 调试：<http://127.0.0.1:10400/docs>
- OpenAPI 描述：<http://127.0.0.1:10400/openapi.json>

## 与收集项目的关系

```text
tools/console：网页 / OpenAPI → 任务控制 → bridge.py
                                    ↓ 单向调用
根目录 collector：数据库解密 → SQL 筛选 → 附件归档 → 去重 / JSONL
```

采集核心不导入本工具、不需要 FastAPI，也不需要本工具运行。停止调试台后，根目录的 `run.cmd once/run` 仍可使用。代码和数据已统一到主项目，工具通过单向适配调用核心。

调试台会读取收集项目的明文快照、状态库与配置。**保存配置、正式采集、重放会修改收集项目的配置或输出**，不是在另一套副本上模拟。配置仍以原 TOML 为准，不另建一套业务配置。

## 启动与停止

本机已具备运行依赖，双击 `start.cmd`，或在本目录运行：

```powershell
C:\veighna_studio\python.exe -B app.py
```

启动后访问上面的面板地址。前台运行时按 Ctrl+C 正常退出：停止后续调度，等待当前任务结束；不要在采集进行中强制结束进程。本项目没有安装 Windows 服务或开机自启动。

**每次启动时，两模块的控制台定时状态默认暂停。** 手动点击各模块“恢复定时”后，按原配置的间隔触发；恢复立即安排首轮。暂停只停止下一次定时触发，不取消正在执行的采集、预览或重放。

本次交付的后台实例 PID 记录在 `.runtime/server-process.json`。这个文件是交付时的运行记录；重新启动后的进程以实际窗口/任务管理器为准。不要只根据旧 PID 杀进程。

停止后台实例时，先在面板暂停两模块，等运行中任务全部结束，再到任务管理器核对进程后结束它。以后可双击 `start.cmd` 前台启动，便于直接使用 Ctrl+C 正常退出。

### 从原独立定时进程切换

`tools/handover.cmd` 会核验收集项目 `data/collector-process.json` 中记录的 PID、创建时间和命令行，取得两个模块的原有文件锁后，才停止该旧进程。这样不会在一轮采集写入中途结束它。最多等待 90 秒，找不到空闲间隔则保留原进程并报错。

若 Windows 明确提示拒绝终止，可右键此脚本选择“以管理员身份运行”。这不是常规面板的启动要求。QQ **首次取钥**仍遵循收集项目自己的管理员运行要求，本项目不扫描进程密钥。

切换后，在面板恢复两模块定时任务。本次交付已完成旧进程切换。检测到记录中的旧进程仍运行或无法核验时，接口拒绝启用另一套定时任务。

### 迁移到另一台机器

使用 Python 3.13 x64，与主项目的 Windows SQLCipher 模块保持一致。在主项目根目录创建虚拟环境并安装核心依赖；需要面板时再安装本工具依赖。以下命令从主项目根目录执行：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m pip install -r tools\console\requirements.txt
.venv\Scripts\python -B tools\console\app.py
```

`start.cmd` 优先使用主项目根目录 `.venv`，不存在时使用本机 `C:\veighna_studio\python.exe`。`console.toml` 的 `collector_root = '../..'` 相对于该配置文件解析，因此从任意工作目录启动仍能定位主项目。端口可在 `console.toml` 改；监听地址固定为 `127.0.0.1`。

## 日常调试

| 操作 | 用途 | 是否写入正式数据 |
|---|---|---|
| 状态卡片 | 查看断点、快照时间、消息数量、待发布事件、运行中任务 | 否 |
| 筛选预览 | 按北京时间范围和当前表单条件查询已有明文快照；返回命中总数及最近样本 | 不刷新数据库、不归档、不写消息批次、不推进断点 |
| 执行一轮 | 调用现有收集项目的默认时间增量流程 | 是，成功后推进断点 |
| 时间段重放 | 使用**已保存**的筛选配置处理所选历史范围 | 是，可能增加修订及附件；不移动定时断点 |
| 消息与附件 | 查看已采集消息最新修订、原始结构、附件状态、图片和下载副本 | 否 |
| 配置保存 | 修改间隔、路径、基础筛选条件；校验并备份原 TOML | 写原配置文件，下一轮生效 |

建议顺序：选择模块 → 调整时间和筛选条件 → 预览 → 需要长期使用时保存配置 → 执行一轮或恢复定时。

筛选表单未保存的内容仅用于预览。重放与定时采集使用磁盘里的配置；页面会提示这一点。预览不刷新快照，因此其结果可能落后于客户端。先执行一轮可刷新快照，但这属于正式采集，会更新断点。

时间使用半开区间 `[开始, 结束)`，界面明确按北京时间解释。预览最长 7 天、样本最多 200 条，面板默认显示 20 条，最长执行 120 秒。正式重放不限制为 7 天，历史范围很大时可能耗时较长、增加磁盘占用。

配置修改采用版本哈希检查，拒绝覆盖已改变的版本；旧文件保留在 `.runtime/config-backups`。账号、状态库、原生 DLL 和 SQL/代码扩展入口只读，面板不提供上传代码或任意 SQL 执行功能。已有可信本地扩展仍按核心原有逻辑生效。

## API 使用

在面板点击“复制 API 凭证”，到 `/docs` 点击 **Authorize** 粘贴，随后可直接调用接口。凭证只对本次服务有效，重启后失效。Swagger 的脚本和样式随项目保存，不依赖外部 CDN。

| 接口 | 含义 |
|---|---|
| `GET /api/status` | 模块状态、控制台调度状态、最近任务 |
| `GET /api/modules/{module}/config` | 原配置与版本哈希，不读取密钥内容 |
| `PATCH /api/modules/{module}/config` | 校验、备份、保存允许修改的字段 |
| `POST /api/modules/{module}/schedule` | `{"enabled":true/false}` 恢复或暂停本控制台调度 |
| `POST /api/modules/{module}/collect` | 正式执行一轮，返回任务 ID |
| `POST /api/modules/{module}/preview` | 只读筛选预览，返回任务 ID |
| `POST /api/modules/{module}/replay` | 按 Unix 秒重放指定时间段，返回任务 ID |
| `GET /api/jobs/{id}` | 任务结果、错误及末尾日志 |
| `GET /api/modules/{module}/messages` | 最新修订的已采集消息，可按正文关键词或会话 ID 筛选 |
| `GET /api/modules/{module}/messages/{seq}/assets/{filename}` | 读取消息引用且位于当前归档目录的文件 |

`module` 为 `wechat` 或 `qq`。任务接口立即返回 `202`，客户端继续查询任务 ID。忙碌或配置版本冲突返回 `409`；参数不合法返回 `422`；缺少凭证返回 `401`。

本机 Python 调试示例（`httpx` 是开发依赖）：

```python
import time
import httpx

client = httpx.Client(base_url="http://127.0.0.1:10400")
client.headers["X-Console-Token"] = client.get("/api/session").json()["token"]
end = int(time.time())
response = client.post("/api/modules/qq/preview", json={
    "start": end - 86400,
    "end": end,
    "limit": 20,
    "filters": {"mentions_all": True}
})
response.raise_for_status()
job_id = response.json()["id"]
while True:
    job = client.get("/api/jobs/" + job_id).json()
    if job["status"] != "running":
        print(job)
        break
    time.sleep(1)
```

不传 `filters` 时预览使用保存的条件；传入时基础条件使用请求中的值及默认值，已有 SQL/代码扩展仍保留。不要在浏览器地址栏放凭证或聊天内容。

## 风险分析

| 风险与触发条件 | 已实现的处理 | 仍需注意 |
|---|---|---|
| 双重调度：原 CLI 与面板同时定时运行 | 检查已记录的旧进程；每模块限制一个控制台任务；沿用核心 OS 文件锁，忙时返回冲突 | 旧进程检测只覆盖记录的那个进程，不能识别所有手动另开的 CLI。一个账号应只由一套定时入口管理；暂停不影响外部进程 |
| 修改配置导致断点丢失或目录混用 | 禁止在面板迁移账号/状态库；禁止输出覆盖或包含原输入、密钥和状态库；保存前校验、备份及版本检查 | 改路径不会搬迁已有数据。修改附件根目录后，旧根目录的归档不会通过新配置继续开放；需要明确迁移方案 |
| 外部编辑器同时改 TOML | 保存前再次比较原文件，避免常见覆盖冲突 | 外部编辑器不遵守本项目锁；不要在运行/保存过程中同时用其他程序改同一配置 |
| 把预览误当正式输出 | 预览独立走数据库只读扫描，不调用刷新、归档或 Store；页面标注快照与只读状态 | 预览仍会创建协调锁文件和本项目任务记录。自定义 `code_file` 是任意可信本地 Python，若它自己有写入行为，调试台无法使它变成纯函数 |
| 强制关闭服务、磁盘满或断电 | 正常退出等待任务完成；核心保留事务、outbox 和原子批次发布；任务记录写失败不会让模块永远忙碌 | 强制终止可能留下临时文件或孤立工作进程。重启将未确认任务标为 `interrupted`，不能假定它已取消；任务结果未返回时核心也可能已完成写入，先查实际断点与输出，再决定重放 |
| 明文聊天和附件泄露 | 固定仅监听回环地址；校验 Host/Origin，拒绝跨站数据请求；数据 API 需要会话凭证；不提供任意文件读取 | 这不是多用户身份系统。可在本机运行程序的用户仍可获取会话凭证；浏览器扩展、截图、下载副本和 `.runtime` 都应按私有数据管理。不要反向代理到公网 |
| 消息正文或附件中有 HTML/脚本 | 页面用 `textContent` 显示正文；图片只允许有限格式内联；HTML/SVG 等附件强制下载；设置 CSP 和 nosniff | 下载后由用户自行打开的文件仍使用系统应用处理，不能因此视为可信文件 |
| 缺失图片或缩略图误当原图 | 保留并展示 `missing`、`thumbnail_only`、`unverified`、`encrypted_only` 等核心状态，以及实际路径和哈希 | 面板不会补下载云端内容或提升图片质量；改变存储目录不会补回原件 |
| 旧消息后补同步、附件后来才下载 | 提供明确的时间段重放入口；不暗中修改默认时间增量规则 | 自动采集只按数据库时间筛选，时间窗之外的补录/编辑/附件仍需重放 |
| 长范围查询与磁盘增长 | 预览 7 天/120 秒上限、任务隔离、同模块互斥；状态页显示运行任务 | 正式重放与解密可能较慢；快照、附件、配置备份、任务记录不会自动清理。本项目只在内存保留最近约 100 个任务，磁盘历史继续保留 |
| 核心内部接口或运行库改变 | 仅 `bridge.py` 适配核心，核心不反向依赖面板；测试通过真实入口验证 | 当前接口不是上游承诺的稳定 SDK。升级收集核心、Python、SQLCipher 或数据库协议后应复测；不能把本次通过外推到未来版本 |
| 服务关闭或系统重启后停止定时采集 | 界面明确展示控制台调度状态；新启动默认暂停 | 没有开机自启。需要重新启动服务并恢复定时，或改用独立 CLI。调试台不是收集核心的必需服务 |

## 扫描间隔与抓取解码强度

两平台独立使用相同配置。面板模块卡片的“扫描与强度”打开对应配置；CLI 读取同一份 TOML，无需控制台服务。

```toml
[schedule]
interval_seconds = 60          # 每轮完成后的等待秒数
refresh_interval_seconds = 0   # 自上次成功采集窗口终点起的最小刷新间隔；0 为每轮
initial_lookback_seconds = 86400

[processing]
intensity = "full"             # metadata / standard / full
```

刷新间隔由用户单独配置，不由强度档位决定。当前保留原有 60 秒扫描间隔、每轮刷新和完整档；未指定新字段的旧配置也采用每轮刷新、完整档。面板扫描间隔支持 5–86400 秒；CLI 支持正整数。刷新间隔支持非负整数，单位为秒。

例如扫描间隔 30 秒、刷新间隔 300 秒，后台每轮结束后等待 30 秒检查；未到刷新时间时不读取旧快照推进断点，也不处理附件。到期后的下一次检查才刷新，实际刷新间隔可能更长。首次采集立即执行；失败不推进断点。手动“执行一轮”遵守刷新间隔，指定时间段的重放绕过间隔、按 source.refresh 决定是否刷新。关闭 source.refresh 后，使用用户管理的明文快照，刷新间隔不生效。

| 强度 | 消息 | 附件与图片 |
|---|---|---|
| 轻量 metadata | 全部匹配消息及原附件元数据 | 不查找、复制、解密媒体文件，附件标记 deferred |
| 标准 standard | 全部匹配消息 | 归档普通本地文件、QQ 本地媒体；微信保留 DAT 密文并复用可读缓存，不做新 DAT 解密或 WXGF 转换 |
| 完整 full | 全部匹配消息 | 在标准基础上尝试微信 DAT 解密与 WXGF 转换，保留原密文变体 |

attachments.enabled 是保存附件的总开关；关闭时三档均不归档、解码。QQ 本地图片通常已可读，标准与完整使用同一路径，不声称完整档会额外恢复云端图片。预览始终只读，不处理附件。

风险：强度不是 CPU/内存硬限额，较大数据库的刷新仍可能占用磁盘；低档会推迟或放弃当前轮附件保存，原缓存被客户端清理后可能无法补齐。配置改变只影响后续执行，不自动回补历史；需要用完整档重放指定时间段。低档重放已归档消息可能产生仅元数据或较低质量的最新修订，原历史事件和归档文件不删除，完整档重放可在源仍存在时补齐。时间筛选仍是 [上次成功终点, 本轮开始)，不添加 ID 游标、重叠窗口或消息截断。

## 注册式筛选与上下文

本工具是主项目 tools/console 目录下的可选工具。筛选与重放页新增“上下文筛选”，支持前后条数、关键词/文件/@所有人，以及扩展规则 JSON。预览和正式采集统一调用核心 scan_filtered，不在页面或后端重新实现邻近逻辑。

完整类型列表、注册接口、TOML 示例与跨轮次限制见主项目 FILTERS.md。基础筛选与扩展规则为 AND；需要包含上下文消息时，不要同时用基础关键词要求当前消息必须命中。未知类型、错误字段或超出范围会拒绝保存；不隐式放宽条件。

规则可能读取时间窗外的邻居，但输出仅含窗内消息。后续消息迟到不会自动回补旧窗，需要重放。上下文用临时 SQLite 表计算，正常完成后删除；强杀进程可能留下含聊天内容的系统临时目录。大范围查询可能增加耗时，未做全历史压力测试。

当前主项目已初始化单一 Git 仓库，本工具没有单独仓库；.runtime 及主项目的数据、密钥、依赖目录不进入版本控制。
